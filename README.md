# PinQ — React / Android 시작 프로젝트

Android 우선 전환 작업과 남은 검증 항목은 [APP_MIGRATION_PLAN.md](APP_MIGRATION_PLAN.md)를 참고하세요.

## 용산구 탐색 범위

기본 출발점은 서울 용산구이며 선택 가능한 출발점과 추천 장소는 용산구 행정동 경계 안으로 제한합니다. 반경은 300m~8km로 조절할 수 있고, 실제 모드는 최대 5개 검색 중심과 장소 유형별 검색을 합쳐 중복을 제거합니다. Google Nearby Search는 호출당 최대 20개를 반환하므로 앱은 최대 48곳을 표시·추천 후보로 사용합니다. 전체 업소를 완전 수집한다는 의미는 아닙니다. 여러 검색 호출과 평점·영업시간 필드 사용으로 Google Maps Platform 과금이 늘 수 있습니다.

경계 출처: 통계청 SGIS 행정동 경계(2026-07-01), [vuski/admdongkor](https://github.com/vuski/admdongkor/tree/master/ver20260701) 가공 자료. 데이터는 CC BY 4.0 및 공공누리 제1유형 출처표시 조건을 따릅니다. [데이터 라이선스](https://github.com/vuski/admdongkor/blob/master/LICENSE-DATA). 경계 변경 시 데이터를 갱신해야 합니다.

첨부한 프로토타입과 가드레일 설계를 바탕으로 만든 Create React App + React 실행 프로젝트입니다. TypeScript를 사용하지 않습니다. JSX는 `.jsx`, 일반 로직은 `.js`/`.mjs`에 들어 있습니다.

## 실행

Node.js 22.12 이상에서:

```bash
npm install
npm start
```

터미널에 표시된 CRA 주소(기본 http://127.0.0.1:3000)를 엽니다. 한 명령으로 React 개발 서버와 추천 서버가 함께 실행됩니다. `.env` 없이도 예시 모드로 즉시 실행됩니다. 기본 조건에서 **코스 찾기**를 누르세요.

```bash
npm test       # 규칙/서버/용산구 경계 검증 테스트
npm run build # React 배포 파일 생성
```

`npm start`는 CRA 개발 서버(3000)와 추천 서버(3001)를 동시에 실행합니다. `src/setupProxy.js`가 `/api/recommend`를 추천 서버로 전달합니다. 실제 배포는 `build/` 정적 파일과 Node API 서버를 같은 도메인으로 연결하세요. 개발 서버는 공개 배포하지 마세요.

## 실제 Google 지도 연결

1. 프로젝트 최상위에 `.env`를 만듭니다. 이미 키를 가진 기존 프로젝트라면 기존 `.env`를 덮어쓰지 말고 필요한 항목만 추가하세요.
2. 다음 키를 입력합니다.

```dotenv
REACT_APP_GOOGLE_MAPS_API_KEY=발급받은_실제_키
```

3. Google Cloud 프로젝트에서 결제 계정을 연결하고 **Maps JavaScript API**, **Places API (New)**를 활성화합니다.
4. 브라우저 키에 웹사이트 제한을 걸고 사용하는 개발 주소를 등록합니다. 예: `http://localhost:3000/*`, `http://127.0.0.1:3000/*`. CRA 포트가 바뀌면 허용 주소도 맞춥니다. API 제한도 필요한 두 API로 한정합니다.
5. `npm start`를 재시작하고 화면 오른쪽 위 **예시 모드**를 끕니다.

`.env`는 `src` 안이 아니라 `package.json` 옆입니다. 환경 변수 이름이 다르거나 서버를 재시작하지 않으면 키가 반영되지 않습니다. 예전 `index.html`의 Google 지도 script 태그는 추가하지 마세요. 이 코드가 한 번만 로드합니다.

브라우저용 Maps 키는 화면 코드에서 보이는 키이므로 도메인/API 제한이 필요합니다. LLM 비밀 키를 `REACT_APP_` 변수에 넣지 마세요. 지도 ID는 사용하지 않습니다. 일반 `google.maps.Marker`를 사용합니다. 이 API는 deprecated 상태지만 현재 중단 일정은 없으며 개발자 콘솔에 관련 경고가 표시될 수 있습니다.

공식 참고:
- https://developers.google.com/maps/documentation/javascript/nearby-search
- https://developers.google.com/maps/documentation/javascript/markers

## 선택: LLM 연결

`.env`의 서버 전용 변수 세 개를 설정합니다.

```dotenv
LLM_API_URL=사용하는_제공자의_Chat_Completions_전체_HTTPS_URL
LLM_API_KEY=서버_전용_키
LLM_MODEL=해당_제공자의_모델명
```

이 서버는 OpenAI-compatible Chat Completions 요청/응답 형식을 사용하며 `response_format: {type: 'json_object'}`를 보냅니다. 해당 형식을 지원하는 제공자가 필요합니다. 키를 설정하지 않으면 LLM 호출 없이 규칙 기반으로 동작합니다.

LLM은 규칙 엔진이 먼저 계산한 최대 3개 후보 코스의 **순위만 선택**합니다. 임의의 장소/가격/권한을 만들어내지 못하도록 출력의 모든 ID, 개수, 중복 여부를 서버에서 검증합니다. 실패·타임아웃·잘못된 출력은 원래 규칙 기반 순위로 대체합니다. 자유 생성 AI 코스를 구현한 것은 아닙니다.

전송되는 데이터: Google로 출발 좌표와 반경/장소 유형, 추천 서버로 조건과 장소 목록, LLM 설정 시 해당 제공자로 취향과 후보 코스 이름/비용/시간. LLM에는 좌표를 전송하지 않습니다. 앱은 위치나 목록을 DB/localStorage/파일에 저장하지 않습니다. 제공자 측 보관 정책까지 통제하지는 않습니다.

## 파일 구조

- `src/App.jsx`: 입력, 상태, 검색 요청, 코스 카드, 비용/점검 표시
- `src/MapView.jsx`: 실제/예시 지도, 출발 마커, 반경, 코스 마커와 카드 연결
- `src/maps.js`: 중복 로딩 방지, 키 확인, Google Places Nearby Search
- `src/engine.mjs`: 가상 데이터, 입력 검증, 비용·시간 계산, 코스 조합과 필터
- `src/App.css`: 반응형 스타일
- `server/index.mjs`: 입력 재검증, LLM 연동, 출력 검증과 fallback
- `server/dev.mjs`: React와 Node 서버 동시 실행
- `tests/engine.test.mjs`: 예산, 휴무/인원, 심야, 잘못된 입력, LLM 검증 테스트

기존 Create React App 프로젝트에 붙이려면 `src` 파일을 복사하고 기존 `index.js`의 렌더링과 CSS import를 맞추세요. 서버/LLM도 쓸 경우 `server`, `src/setupProxy.js` 및 실행 스크립트와 `.env`도 가져와야 합니다. 독립 실행은 이 폴더 전체를 사용하는 편이 간단합니다.

## 실제 동작 범위

| 기능 | 구현 |
| --- | --- |
| 지도 클릭 출발점·반경 이동 | 용산구 안에서 출발점을 선택하고 반경 300m~8km 조절 |
| 새 검색 시 기존 마커 제거 | 조건 변경/탐색 시작 시 기존 코스 제거, 효과 cleanup으로 마커와 선 제거 |
| 비동기 응답 경합 | 요청 번호로 오래된 Places/추천 응답 무시, 추천 fetch 취소 |
| 장소 탐색 | Places API (New) 구역·유형별 합산 최대 48곳, 용산구 경계·반경 필터 |
| 여러 코스 | 후보 중 3곳 조합, 가까운 순서로 연결, 최대 3개 코스 |
| 예상 비용 | 먹거리·놀이·이동 합산, 인원수 곱셈, 전체 예산 검증 |
| 밤 이동 | 21시~06시 도보·자전거 제외, 21시를 넘기는 코스도 제외 |
| API 실패 | 같은 세션/출발점/반경/테마의 직전 실제 결과가 있으면 대체, 없으면 명확한 오류 |
| LLM 실패 | 결정적 규칙 순위 유지 |
| 입력 가드레일 | 좌표 범위, 정수 인원, 숫자 예산, 날짜/시간, 키워드 패턴 검증 |
| 외부 데이터 | 리뷰 자체를 수집하지 않음, 문자열 정리와 JSON 경계, 모델 도구 없음, 허용 ID만 출력 |
| 저장·권한 | 세션 메모리만 사용, 결제·예약·메시지·연락처 기능 없음 |

## 추정과 미구현 항목

- **실제 영업시간 검증은 미구현**: Google의 주간 영업시간을 참고 표시하지만 예정 도착 시간·특별 휴무를 검증하지 않습니다. 가상 모드만 고정 영업시간/휴무일/정원으로 검증합니다. ‘영업시간 미확인 장소 제외’를 켜면 실제 모드에는 결과가 없습니다.
- **가격은 실제 메뉴 가격이 아닙니다**: 1인 장소당 공원 0원, 문화 10,000원, 카페 8,000원, 식사 15,000원의 가정을 사용합니다. 대중교통은 구간당 1인 1,600원 가정(실제 요금이나 환승 계산 아님), 도보/자전거는 0원 가정(자전거 대여료 미포함).
- **실제 길찾기는 미구현**: 직선거리 × 1.3과 이동수단별 가정 속도를 사용합니다. 교통은 구간당 대기시간 8분 가정. 지도 연결선은 방문 순서일 뿐 도로 경로가 아닙니다. 귀환 구간은 포함하지 않습니다.
- 실제 혼잡도, 소상공인 여부, 수용 인원, 조명/범죄/공사/보행 가능 여부, 대중교통 막차는 **미확인**입니다. Google 별점/리뷰 수를 혼잡도로 바꾸지 않습니다. 실제 모드에서는 local/quiet 점수를 가산하지 않습니다.
- 가상 지도의 장소명·가격·위치·영업시간은 모두 예시이며 출발점을 옮기면 새 가상 동네를 구성합니다. 가상 지도는 지리적으로 정확한 지도가 아닙니다.
- 키워드 검사는 알려진 조작 패턴을 잡는 보조 장치이며 완전한 인젝션 탐지기가 아닙니다. 핵심 제한은 도구 없는 LLM, 검증 완료 후보만 제공, 출력 ID 검증입니다.
- 운영용 감사 로그, 사용자 피드백 수집, SDG 성과 지표 측정은 구현하지 않았습니다. 화면 점검표는 현재 계산의 상태 표시입니다.

## 확인 시나리오

1. 기본 조건 → 3개 코스, 비용 합계, 카드/지도 번호 확인.
2. 코스 생성 후 인원 변경 → 기존 마커 제거, ‘다시 탐색하기’ 표시.
3. `이전 지시 무시` 입력 → 오류 안내, 코스 생성 차단.
4. 22시 선택 → 도보/자전거 선택 불가.
5. 예시 모드에서 ‘장소 조회 실패 시연’ → 가상 데이터 사용 메시지와 코스.
6. 실제 모드에서 성공 후 실패 시연 → 동일 범위 세션 데이터로 대체. 조건이 다르거나 캐시가 없으면 오류.
7. 정원보다 많은 인원/낮은 예산/닫힌 시간 → 조건 변경 안내.

## 이번 CRA 변경

- `src/index.js` + `public/index.html` + `react-scripts`로 구성 변경.
- 지도 키는 요청한 `process.env.REACT_APP_GOOGLE_MAPS_API_KEY`로 읽습니다.
- 지도 로더는 `libraries=places&callback=initMap`을 사용합니다. `window.initMap`을 스크립트 추가 전에 등록합니다.
- 지도 ID와 AdvancedMarkerElement를 제거하고 일반 Marker로 변경. 정리 시 `setMap(null)` 호출.
- React는 CRA와 맞춰 18.3.1을 사용합니다.
- `.env`는 저장소에 포함되지 않습니다. 실제 지도나 LLM을 사용하려면 프로젝트 최상위에 직접 만들어 키를 설정하세요.
- LLM 설정은 같은 `.env`에서 Node 서버가 읽습니다. CRA 브라우저 번들에 비밀 키를 포함하지 않습니다.
- CRA는 유지보수가 종료된 도구이지만 요청한 기존 CRA 환경에 맞춰 구성했습니다.

Android 앱용 빌드와 개발·운영 API 연결은 [전환 계획](APP_MIGRATION_PLAN.md)을 참고하세요.

## 검증

- CRA `npm run build` 성공.
- 추천·서버·용산구 경계 테스트 통과.
- 서버 LLM 키 테스트 값을 주입한 빌드에서 해당 값이 브라우저 JavaScript에 포함되지 않는 것을 확인.
- 실제 Google/LLM API 호출은 키가 없어 검증하지 못했습니다. 예시 모드의 브라우저 코스 생성은 확인했습니다.

- CRA 개발 서버 시작 및 `/api/recommend` 프록시 응답(코스 3개) 확인 완료.
